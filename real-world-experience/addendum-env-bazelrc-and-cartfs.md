# Addendum: How `env.bazelrc` and CartFS `output_base` Are Generated in `studio-main`

## 1. Origin of `env.bazelrc` (Not `repo sync`)

`env.bazelrc` at the root of `~/projects/studio-main` is **not** generated by `repo sync` or `<copyfile>`/`<linkfile>`. It is created when the user runs `./build/bazel/env/setup` (which executes `build/bazel/env/setup_dev_env.py` from the `platform/build/bazel` repository).

 meanwhile, the workspace root `.bazelrc` (which is a `<linkfile>` symlink to `tools/base/bazel/toplevel.bazelrc`) includes it conditionally via:

```ini
try-import %workspace%/env.bazelrc
```

---

## 2. Exact Mechanics of `build/bazel/env/setup_dev_env.py`

When `./build/bazel/env/setup` runs:

1. **Workspace Root Discovery (`find_workspace_root()`)**:
   Walks upward from `pathlib.Path(__file__).parents` (`build/bazel/env/setup_dev_env.py`) looking for:
   - `(path / '.repo').is_dir()` (standard `repo` checkout), or
   - `(path / '.supermanifest').exists()` (Cog checkout).
   If neither exists in any parent directory, it raises `FileNotFoundError('Could not find workspace root')`.

2. **Platform Detection (`detect_platform()`)**:
   Inspects `/etc/lsb-release` on Linux:
   - `GOOGLE_ROLE=desktop` -> `Platform.GLINUX_DESKTOP`
   - `GOOGLE_ROLE=laptop` -> `Platform.GLINUX_LAPTOP`

3. **`env.bazelrc` Generation (`build_env_bazelrc(host_platform, workspace_root)`)**:
   - On `GLINUX_DESKTOP`:
     - Emits `import %workspace%/tools/vendor/google/bazel/glinux.bazelrc` (credential helper and BES project header).
     - Checks `if pathlib.Path('/google/cartfs/mount').exists():`.
     - Computes `workspace_hash = hashlib.md5(str(workspace_root).encode('utf-8')).hexdigest()`.
       For `/usr/local/google/home/jomof/projects/studio-main`, `md5` is `82f1a270dd3e54436acdeaa58b68077a`.
     - Emits:
       ```ini
       startup --output_base=/google/cartfs/mount/82f1a270dd3e54436acdeaa58b68077a
       ```
   - On all other platforms:
     - Emits `build --google_default_credentials`.
   - Always appends:
     ```ini
     build --config=rcache
     build --config=release
     ```

## 3. What CartFS Is (and Public vs. Internal Availability)

- **CartFS is a Google-internal FUSE-based filesystem** (`cartfs` service mounted at `/google/cartfs/mount` on gLinux Cloudtops/workstations). It is **not** publicly available as an open-source FUSE daemon.
- **Purpose for Bazel `output_base`**: CartFS deduplicates identical build artifact content across multiple workspace output directories on the same machine while maintaining isolated directory trees and metadata (`mtime`, Bazel server locks) per `/google/cartfs/mount/<md5(workspace_root)>` subdirectory.
- **Public Code Footprint**: Although the CartFS daemon is Google-internal, the check `CARTFS_MOUNT = '/google/cartfs/mount'` in `build/bazel/env/setup_dev_env.py` is committed directly in the public AOSP `platform/build/bazel` repository (and similar path checks appear in public Fuchsia `fx` tooling). Because `git-repo-worktree` is a public open-source tool, any handling of `env.bazelrc` or `output_base` in `git-repo-worktree` should remain mechanism-agnostic and avoid hardcoding proprietary internal service dependencies.

## 4. Architectural Implications for `git-repo-worktree` v2

1. **Why `./build/bazel/env/setup` Fails in `git-repo-worktree` v1**:
   - In v1, `<worktree>/.repo` does not exist (only `<worktree>/.repo-worktree/`), so `find_workspace_root()` in `setup_dev_env.py` raises `FileNotFoundError: Could not find workspace root`.
   - Furthermore, if `build/bazel` is materialized as `symlink-shared`, `pathlib.Path(__file__)` resolves through the symlink back into `~/projects/studio-main/build/bazel/env/setup_dev_env.py`, causing `find_workspace_root()` to return `~/projects/studio-main` and overwrite the source workspace's `env.bazelrc` instead of creating `<worktree>/env.bazelrc`.

2. **Model E1 (`.repo/` Synthesis) + Non-Symlinked Directories Make `./build/bazel/env/setup` Work Natively**:
   - With Model E1 creating a real `<worktree>/.repo/` directory and FUSE CoW / `--no-checkout` replacing `symlink-shared`, running `./build/bazel/env/setup` inside `<worktree>` automatically resolves `workspace_root = <worktree>` and generates `<worktree>/env.bazelrc` with `startup --output_base=/google/cartfs/mount/<md5(worktree_root)>`.

3. **Smart Path/Hash Rewriting When Copying Untracked Root Configs (`env.bazelrc`)**:
   - When `git repo-worktree add` copies untracked root config files like `env.bazelrc` from `<source_root>` to `<worktree_root>`:
     - Rather than blindly copying `startup --output_base=/google/cartfs/mount/<md5(source_root)>` (which causes Bazel server lock contention with the main workspace) or deleting the `--output_base` line (which loses CartFS deduplication and falls back to `~/.cache/bazel`), `git-repo-worktree` can generically replace occurrences of:
       - `<source_root>` -> `<worktree_root>`
       - `<md5(source_root)>` -> `<md5(worktree_root)>`
     - This is completely generic (requires zero Google-internal dependencies in `git-repo-worktree`), preserves CartFS artifact deduplication when `/google/cartfs/mount/<md5>` is used, and isolates each worktree's Bazel server lock and `output_base`.

4. **Clean Teardown on `git repo-worktree remove`**:
   - Before unmounting/deleting `<worktree_root>`, if `<worktree_root>/env.bazelrc` specifies `startup --output_base=<path>` (or if `bazel` was used), `remove` can shut down the worktree's Bazel server and optionally prune the worktree-specific `output_base` directory (`/google/cartfs/mount/<md5(worktree_root)>` or `~/.cache/bazel/_bazel_$USER/<md5(worktree_root)>`).

## 5. Actionable Conventions for the Reviewing Agent (No CartFS Required)

> [!IMPORTANT]
> **You (the reviewing/implementing agent) do NOT need CartFS installed in your environment**, and `git-repo-worktree` must **never** hardcode `/google/cartfs/mount` or depend on CartFS APIs/binaries.
>
> Instead, `git-repo-worktree` automatically takes advantage of CartFS whenever it happens to be present on a user's machine simply by following **four purely generic conventions**:

1. **Convention 1 — Real `<worktree>/.repo/` Directory & Non-Symlinked Project Directories**:
   - Synthesize `<worktree>/.repo/` as a real directory (Model E1) and ensure project directories (`<worktree>/build/bazel`, etc.) are real directories rather than `symlink-shared` symlinks to `<source_root>`.
   - *Why this enables CartFS*: Scripts like `./build/bazel/env/setup` walk `Path(__file__).parents` looking for `(path / '.repo').is_dir()`. Following this convention ensures those scripts resolve `workspace_root = <worktree>` instead of failing with `FileNotFoundError` or escaping via symlinks to `<source_root>`.

2. **Convention 2 — Generic `<source_root>` and `<md5(source_root)>` Substitution in Copied Root Configs**:
   - When `git repo-worktree add` copies untracked root config files (`env.bazelrc`, `user.bazelrc`, `local.properties`) from `<source_root>` to `<worktree_root>`:
     - Compute `source_md5 = md5_hex(source_root_str)` and `worktree_md5 = md5_hex(worktree_root_str)` as lowercase 32-character hex strings of the canonical UTF-8 path without a trailing slash (matching Python's `hashlib.md5(str(workspace_root).encode('utf-8')).hexdigest()`).
     - Replace every occurrence of `source_root_str` with `worktree_root_str`, and every occurrence of `source_md5` with `worktree_md5`.
   - *Why this enables CartFS*: When a user's source workspace has `startup --output_base=/google/cartfs/mount/<source_md5>` in `env.bazelrc`, this generic string replacement automatically transforms it into `startup --output_base=/google/cartfs/mount/<worktree_md5>`—giving the worktree both CartFS artifact deduplication and an isolated Bazel `output_base` without `git-repo-worktree` knowing anything about CartFS.

3. **Convention 3 — Generic `startup --output_base=<path>` Inspection on `remove`**:
   - During `git repo-worktree remove`, scan `<worktree>/*.bazelrc` for `startup --output_base=<path>`.
   - Only shut down / clean up `<path>` if `<path>` contains `<worktree_md5>` or `<worktree_root>` (guaranteeing that `remove` never touches `<source_root>`'s `output_base`).

4. **Convention 4 — How to Test Without CartFS**:
   - Write integration tests using standard temporary directories (e.g. `/tmp/...`) by seeding `<source_root>/env.bazelrc` with:
     ```ini
     import %workspace%/tools/vendor/google/bazel/glinux.bazelrc
     startup --output_base=/tmp/mock-dedup-mount/<source_md5>
     build --config=rcache
     ```
   - Assert that `git repo-worktree add` produces `<worktree_root>/env.bazelrc` with `startup --output_base=/tmp/mock-dedup-mount/<worktree_md5>`.
